# Experiment Report

## Title
Team Project Repository with Branches, Pull Requests and README Documentation

## Aim
To demonstrate collaborative software development by managing a GitHub repository with branches and pull requests.

## Theory
Git is a distributed version control system. It records changes to files and helps developers work together. GitHub hosts Git repositories online and provides collaboration features such as branches, pull requests, code review, and merge history.

A branch is an independent line of development. It allows a contributor to make changes without directly modifying the main branch. A pull request (PR) is a request to review and merge changes from one branch into another. The README file explains the purpose, structure, setup, and usage of a project.

## Procedure
1. Open the GitHub repository.
2. Create a new branch from main.
3. Add or modify project documentation.
4. Stage and commit the changes.
5. Push the branch to GitHub.
6. Open a pull request from the working branch to main.
7. Review the changed files and merge the pull request.
8. Verify the merged files in main.

## Observation
The repository uses a dedicated working branch for the experiment. Project documentation and contribution details are stored as version-controlled files. The pull request provides a visible record of the proposed changes and their integration.

## Result
The GitHub team repository workflow was completed with branch-based development, documentation, and a pull-request-based merge process.
